# ipcprims v0.2.2

> Released: 2026-07-06

**Breaking wire change for token-authenticated peers:** the optional `auth_token` handshake field now carries bytes rather than a UTF-8 string. No-auth peers remain compatible because the field is omitted. Older token-authenticated peers that send string tokens intentionally fail closed. Consumers using token auth should upgrade both sides together.

This release adds the async TypeScript peer surface and hardens auth-token handling across Rust, C FFI, Go, and TypeScript bindings.

## Highlights

- **TypeScript async peer API**: TypeScript bindings now expose `AsyncPeer`, `AsyncListener`, async receive methods, async channel receivers, and promise-based send/ping/shutdown backed by Rust `AsyncPeer`.
- **Abortable pending receives**: Async TypeScript receives support `AbortSignal` cancellation without keeping Node/Bun timers alive unnecessarily.
- **Opaque token bytes**: Auth tokens now cross Rust, C, Go, and TypeScript as byte buffers rather than UTF-8 strings.
- **Zeroizing ownership**: ipcprims-owned token buffers use zeroizing storage; FFI token retrieval returns caller-owned bytes that must be released with the dedicated zeroizing token free function.
- **Explicit server retrieval**: Server peers expose a distinct no-token state and clear stored token material after retrieval.
- **Binding examples**: Go and TypeScript examples use constant-time comparison patterns with clean length-mismatch rejection before treating a peer as authenticated.

## Breaking Change

The optional `auth_token` handshake field now carries bytes rather than a UTF-8 string.

Compatibility impact:

- no-auth peers remain compatible because the field is omitted;
- older token-authenticated peers that send string tokens intentionally fail closed;
- no known deployed cross-version token-authenticated peers exist for this release window, so consumers using token auth should upgrade both sides together.

## Verification

- TypeScript binding tests cover async connection, send/receive, ping, shutdown, abortable pending receive, and timer-liveness behavior.
- Rust handshake tests cover arbitrary byte tokens, interior NUL bytes, oversized rejection, present-empty rejection, legacy string rejection, debug redaction, and token retrieval clearing.
- FFI tests cover auth token pointer/length validation, retrieve-present/no-token states, and zeroizing free usage.
- Go and TypeScript binding tests cover authenticated connection, server-side retrieval, empty-token rejection, and constant-time comparison examples.
